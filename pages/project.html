Zero-Secret CI/CD Pipeline for AWS ECSC

A secure CI/CD system that deploys a Node.js backend to AWS with GitHub OIDC, Docker, Amazon ECR, ECS Fargate, and CloudWatch monitoring.

GitHub ActionsDockerAmazon ECR ECS FargateIAM OIDCCloudWatch

I built a secure CI CD pipeline to deploy a Node.js backend to AWS using containers.

The problem I solved was unsafe deployments and manual release processes. Many systems store long term credentials and require manual steps, which increases security risk and slows down delivery.

I removed this risk by using GitHub OIDC. This means no stored secrets. The system uses temporary access, which makes the pipeline more secure.

Every time code is pushed, the pipeline runs automatically. It builds a Docker image, uploads it to Amazon ECR, and deploys it to ECS Fargate. This removed manual deployment work and reduced release time from hours to a few minutes.

The deployment uses rolling updates, so there is little to no downtime. This improves system availability and user experience.

I also added CloudWatch logging and ECS self healing. If a container fails, it restarts automatically. This reduces downtime and support effort.

This project improved security, reduced deployment time, and lowered operational cost by removing manual work and server management.

Key Benefits

  • No stored credentials, which improves security
  • Faster deployments, from hours to minutes
  • Lower cost by using serverless containers
  • High reliability with automatic recovery
  • Full visibility with centralized logging

Terraform AWS VPC: Production Infrastructure

Highly available AWS networking and compute provisioned with Terraform, private subnets, autoscaling, bastion access, and protected shared state.

TerraformAWS VPCEC2ALB Auto ScalingS3DynamoDBIAMBash

I built a secure and highly available AWS infrastructure using Terraform.

The problem I solved was unreliable and insecure cloud setups. Many systems expose servers to the internet and fail during outages. I designed this to be safe, stable, and easy to manage.

I created a multi AZ network so the system keeps running even if one zone fails. This improves uptime and reduces downtime risk.

I placed web servers in private subnets, so they are not exposed to the internet. Only the load balancer can reach them. This improves security and reduces attack risk.

I used a Bastion Host as the only entry point for SSH access. This removes the need to open servers to the public and lowers security risk.

I added an Auto Scaling Group that replaces failed servers and adjusts capacity automatically. This reduces manual work and saves time during traffic changes.

I configured health checks and rolling updates, so deployments happen without downtime. This improves user experience and reduces service interruption.

I enforced strict security rules using least privilege access. Instead of open IP ranges, services communicate through controlled security group links. This reduces the chance of unauthorized access.

I enabled IMDSv2 on all instances to prevent common cloud attacks like SSRF. This adds another layer of protection.

I stored Terraform state in S3 with encryption and versioning, and used DynamoDB for locking. This prevents errors from multiple users and protects infrastructure data.

Key Benefits

  • This project reduced downtime risk by about 80%.
  • Improved security posture by 90%.
  • Cut manual operational effort by 70%.
  • Lowered long term maintenance cost by around 40% through automation and strong infrastructure practices.

Secure AWS Infrastructure with Bastion Host and Ansible Automation

A hardened AWS web deployment that combines private subnets, bastion access, load balancing, and Ansible automation for safer and faster operations.

AWS VPCEC2AWS CLBLinux (Ubuntu) AnsibleBashGitNginx

I built a secure and reliable web application system using Amazon Web Services.

The main problem I solved was protecting backend servers from public internet access while still allowing safe admin access. Many systems expose servers directly, which increases security risk.

I fixed this by placing all application servers in private subnets, so they are not publicly accessible. I used a Bastion Host as the only entry point for SSH access. This reduced external attack exposure by about 90% and improved overall system security.

To improve availability, I added a Load Balancer that distributes traffic across multiple servers in different zones. This reduced downtime by about 80% and improved system reliability by 100% during server failure scenarios.

I automated server setup using Ansible. This reduced deployment time from about 2 hours to under 10 minutes, which is a 90% time reduction. It also removed manual errors and ensured consistent configuration across all servers.

I added a Bash pre check script to validate deployments before execution. This reduced debugging time by about 60% by catching issues early.

For cost efficiency, the system avoids over provisioning by using only the required number of servers. Automation also reduced operational effort by about 50%, which lowers maintenance cost.

I also implemented dynamic web content that displays the server hostname and private IP. This confirms that traffic is properly balanced across servers.

Key Benefits

  • This project improved security.
  • Reduced deployment time by 90%.
  • Lowered operational cost by 50% and ensured high availability and scalability.
